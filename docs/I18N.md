# Localization (i18n)

Tungsten ships its own messages. Application authors only supply their labels and
optional overrides. This applies to the form, default design and editor; the
website's language selection is independent of the package's supported languages.

## Supported package languages

| Tag | Language |
| --- | --- |
| `en` | English |
| `sk` | Slovak — Slovenčina |
| `hu` | Hungarian — Magyar |
| `de` | German — Deutsch |
| `es` | Spanish — Español |
| `fr` | French — Français |

```tsx
<Tungsten schema={schema} language="de" onSubmit={onSubmit} />
```

No custom catalog is necessary for Tungsten messages. English is the default.
Regional tags such as `de-DE`, `es-MX` and `fr-CA` use the base-language messages
and preserve region-specific formatting. Catalog selection is not browser-language
detection: the host selects `language` or uses a shared language provider.

All JSON files ship in the package, but non-English catalogs are separate dynamic
imports. The provider loads only the selected language and configured fallback;
English remains the built-in last resort. These imports are package assets and do
not use the application's API executor. Successfully imported modules are cached
by the module loader.

RTL layout and its keyboard/bidirectional-text qualification remain future work.
Hebrew, Arabic and other RTL languages are not advertised as supported designs.
A custom catalog can supply text in any language, but does not implement RTL.

## Literal labels and custom keys

A German-only application can write `view: { label: 'Vorname' }` and provide no
translation JSON. Every displayed string is looked up; an unmatched string is
displayed unchanged. Field keys and submitted values are never translated.

For applications with several languages, use your own flat string keys:

```json
{
  "contact.name": "Vorname",
  "contact.nameHint": "Wie heißen Sie?",
  "tg_ui_submit": "Antrag abschicken"
}
```

```tsx
import de from './locales/de.json'
const config = { i18n: { translations: { de } } }
// Schema: view: { label: 'contact.name', placeholder: 'contact.nameHint' }
<Tungsten schema={schema} config={config} language="de" onSubmit={onSubmit} />
```

The same JSON provides application translations and Tungsten overrides. Supply
only the keys you need. Dots are literal parts of flat keys, not nested-object
paths. Custom catalogs use the exact configured language key: for `language="de-DE"`,
configure `translations: { 'de-DE': de }`. Built-in catalogs alone use the base tag.

Resolution order is:

1. Selected custom catalog.
2. Selected bundled catalog.
3. Configured fallback-language custom catalog.
4. Configured fallback-language bundled catalog.
5. Bundled English.
6. Original string or message key.

`fallbackLanguage` defaults to `en`. An empty string intentionally displays empty
text, even if another catalog contains that key. `null` is invalid, not a fallback
marker. Delete an override to restore the default. Malformed catalogs fail
atomically and expose a provider error while usable bundled messages remain.

## An unsupported language and the blank template

Download the template from the website's
[Localization guide](https://tungsten.myoon.sk/documentation/?guide=localization#custom-language),
or copy `@myoonhq/tungsten/locales/template.json` into your project. It contains
every system key with `""` as its value. It is a template, not a ready-to-use
catalog: importing it unchanged intentionally empties all system messages.

Fill the entries for your language, delete entries you want to leave at their
fallback, or copy only selected keys into an existing application JSON. Preserve
the parameters documented in the key reference. For example:

```tsx
import cs from './locales/cs.json'
const config = { i18n: { translations: { cs }, fallbackLanguage: 'en' } }
<Tungsten schema={schema} config={config} language="cs" onSubmit={onSubmit} />
```

Missing keys fall back to English here. To use another supported fallback, set
its language tag. Official catalogs can also be imported through
`@myoonhq/tungsten/locales/<language>.json`. The English catalog is a populated
reference, available separately from the blank template.

## Existing keys, parameters and plurals

The [searchable system-key reference](https://tungsten.myoon.sk/documentation/?guide=localization#system-message-keys)
lists every key, its purpose, English default and parameters. The same inventory
is exported as `@myoonhq/tungsten/locales/reference.json`; supported-language names
are exported as `@myoonhq/tungsten/locales/languages.json` and `supportedLanguages`
from the React entry point. Neither the template nor the reference is a language.

Keys beginning with `tg_` belong to Tungsten. Use your own namespace for application
labels. The reference groups field validation, form controls/accessibility,
editor controls, authoring settings, schema diagnostics, data-source messages,
requests, uploads, date/time messages, translation errors and warnings.

Strings interpolate `{parameter}`. Preserve names and case, including positional
parameters such as `{p0}`. Values are literal unless explicitly supplied as a
nested `{ messageKey, params }` message. React escapes text; catalogs cannot
execute code or create HTML.

```json
{
  "tg_validation_min_length": "Mindestens {min} Zeichen erforderlich.",
  "tg_ui_errors": { "one": "{count} Fehler", "other": "{count} Fehler" }
}
```

Plural messages use `Intl.PluralRules` with numeric `count`; `other` is required.
Custom catalogs may omit other categories and use `other` as their fallback.
Bundled catalogs include all categories for their base language. Empty strings
are also valid overrides for keys normally containing plural objects.

## Loading and switching

`translations` accepts imported JSON objects or browser-accessible JSON URLs.
`i18n: { directory: '/locales' }` loads `/locales/<language>.json` for custom catalogs.
The directory is a web URL. Requests use the shared API executor with operation
`i18n`, cancellation and request deadlines, without inherited API credentials.

`TungstenLanguageProvider` can wrap several forms or an editor. Children without
explicit language/i18n configuration inherit it. `useTungstenLang()` exposes `t`,
`language`, `loading`, `error` and `reload()`; `TungstenLang` renders visible text.

The previous presentation remains while replacement catalogs load; obsolete
completions are ignored. Switching language or reloading translations does not
reset entered values, rerun rules, fetch data sources, reload the schema or emit
state/autosave events. Gregorian dates and digits 0–9 remain the date-entry policy;
language changes affect ordering, separators and labels, not stored dates.

## Maintenance and CI

Add system messages to `api/src/locales/en.json` and every supported catalog, then
run `pnpm --filter @myoonhq/tungsten generate:locales` to update the blank template
and reference. When adding a language, add its dynamic import and its name to
`languages.json`, and update this documented list.

`pnpm --filter @myoonhq/tungsten test:i18n` checks all catalogs, interpolation,
plural categories, automatic provider loading, overrides, empty strings,
fallbacks and the generated inventory. The named CI Localization stage runs
these tests; production-browser tests exercise language assets from the packed
package in every configured browser project.
